欢迎使用纯静态博客骨架

2026-09-12 · 建站 说明

这是一个可以直接 push 上线的静态博客骨架。它的全部内容是 HTML、一份 CSS、一份原生 JS—— 没有生成器、没有 npm 依赖、没有构建步骤，也没有需要定期升级的工具链。

它的目标是：把「写博客」这件事，从「维护一套工具链」里解放出来。

这个骨架里有什么

路径作用
index.html首页：站点介绍 + 搜索框 + 文章列表
about.html关于页
posts/*.html文章，一篇一个文件
assets/style.css全部样式，含暗色主题与打印样式
assets/main.js暗色模式、目录、代码复制、搜索（渐进增强）
feed.xmlRSS 订阅源
search-index.json站内搜索索引
.nojekyll一行空文件，阻止 GitHub Pages 跑 Jekyll，见下文
tools/可选工具：构建脚本、页面模板。不参与发布也可

发一篇文章只要三步

  1. 把 tools/post-template.html 复制到 posts/，改个文件名；
  2. 改其中的标题、<meta name="post:date">、<meta name="post:tags"> 和正文；
  3. push。首页列表和 RSS 要么手改，要么跑一句 node tools/build.mjs 自动生成。
cp tools/post-template.html posts/my-new-post.html
# 编辑 posts/my-new-post.html
node tools/build.mjs       # 可选：刷新首页列表 / RSS / 搜索索引
git add -A && git commit -m "post: my new post" && git push

tools/build.mjs 是可选的。不运行它，站点也完整可用—— 所有 HTML 里已经是展开好的最终内容。它存在的唯一理由，是消除「改一次导航要改 N 个文件」的重复劳动。

部署到 GitHub Pages

新建仓库，把文件推上去，然后：

  1. 进入仓库 Settings → Pages；
  2. Source 选 Deploy from a branch；
  3. 分支选 main，目录选 / (root)，保存；
  4. 等约一分钟，访问 https://<用户名>.github.io/<仓库名>/。

必须保留 .nojekyll 这个空文件。 从分支部署时，GitHub Pages 默认会让 Jekyll 先处理一遍你的文件， 而 Jekyll 会忽略所有以 _ 下划线开头的文件和目录。 放一个空的 .nojekyll 就彻底关掉它。这是纯静态方案唯一的隐藏陷阱。

如果你用自定义域名，把 CNAME 文件（内容为你的域名）放到仓库根目录即可。 另外记得把 tools/build.mjs 顶部的 SITE_URL 改成真实地址，RSS 里的链接才正确。

它刻意不做什么

这套方案的代价只有一个，必须说清楚：

共享布局的维护成本从 O(1) 变成 O(n)。 改一次导航栏或页脚，用生成器的方案只改一个模板文件，这里要改每一个 .html。 文章少时无所谓；到三十篇以后，你会想跑 tools/build.mjs，或者干脆上 Jekyll。

除此外也都是有意的取舍：

  • 没有评论系统——需要的话接入 Twikoo / Waline 之类的第三方服务，加一段 script 即可；
  • 没有标签页和归档页——文章少时没必要，多了可以自己生成；
  • 没有自动分页——一页列完，简单直接；
  • 没有访问统计——可以用不蒜子之类的第三方脚本，一行标签的事。
